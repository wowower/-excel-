## 一 项目背景与实际问题

获得信息和表达意愿是参与学习、工作与社区生活的基础。辅助需求的障碍可能来自输入方式、内容形式、复杂操作、缺少合适设置，以及需要持续联网或重复注册。WHO 将沟通、认知与字幕等数字产品纳入辅助技术范围，同时强调产品之外的服务与获取障碍。[S01](https://www.who.int/news-room/fact-sheets/detail/assistive-technology)

国内无障碍环境建设相关法律对字幕、大字和信息交流提供了政策背景。法律支持需求的公共价值，但不自动证明本项目已达到法定标准、具备资助资格或应当被采购。[S03](https://gxca.miit.gov.cn/zwgk/zcwj/flfg/art/2024/art_340a68cb6a8e45ae81c121630dd37346.html)

本项目已整理 29 条公开来源，覆盖国际组织、当事人相关机构、技术标准、现有产品与公开使用反馈。具体需求包括沟通板输入方式可选、阅读显示与位置可调、字幕能够被人工复核、任务步骤清楚且可以恢复，以及内容提供者能够识别常见结构问题。公开证据能够说明问题值得验证，但不能代替本项目的用户访谈。

## 二 服务对象与适用边界

首轮对象是能表达使用意愿、愿意尝试相应工具的成人，以及经其同意参与设置的协助者。项目不要求提供诊断证明，不把某一残障类别的所有人视作同质用户，也不通过照护者意见替代当事人的选择。

软件不提供医疗诊断、康复处方、服药建议、眼控识别、自动手语翻译、环境危险报警或路线安全保障。需要专业 AAC 系统、出版物阅读器、专业字幕编辑器及审计服务的场景，应当优先评估成熟产品。

## 三 项目目标

在 24 周内完成一轮以当事人参与为核心的验证，形成可复现的测试材料、修复记录及公开版本；建立用户可理解的数据保存、导出与删除流程；明确每个模块的可用场景和不适用场景。项目的成功标准是自主选择与任务可达性改善的证据，而不是简单追求功能数或下载量。

## 四 建设内容与已有基础

| 模块 | 当前可运行能力 | 后续建设重点 |
| --- | --- | --- |
| 表达板 | 短语 句子组合 本地语音 大字展示 扫描 | 外接开关与不同触发方式实测 |
| 轻阅读 | 纯文本 逐段显示 偏好调整 本地朗读 | 真实阅读任务与辅助技术兼容 |
| 字幕工作台 | 时间文字编辑 偏移 检查 导出 | 本地媒体同步和听障共同复核 |
| 一步任务卡 | 分步 暂停 退回 保存 计时 | 用户自选任务的恢复体验 |
| 网页检查台 | 静态源码线索 两色对比度 报告 | 规则误报边界与人工测试路径 |

软件采用原创 HTML、CSS 和 JavaScript，无运行时第三方依赖。通用界面提供键盘导航、可见焦点、大字号、配色选择、明文存储提示及 JSON 备份。核心算法已有 56 项自动断言；初步浏览器检查已覆盖模块的主要数据流程。完整环境和测试边界见随附用户指南及测试记录。

当前原型和文档是技术基础，不构成已完成的服务试点。没有用户留存、付费、临床结果、合作机构或采购承诺。正式立项后应将这些未知问题纳入阶段目标，而不是填成已实现业绩。

## 五 方案特点与创新边界

本项目拟验证的是一条实施路径：用统一的本机处理、清楚的操作和可带走的数据，降低小规模辅助场景的部署与试用成本。五个模块共享控制方式和数据约定，用户可以只选需要的模块。

这种组合属于工程与服务流程设计，不声称首创 AAC、字幕编辑或无障碍检查。Cboard、AsTeRICS、Thorium、Subtitle Edit 和成熟评估工具都已存在。项目将对照这些方案，必要时选择适配、培训或回馈现有开源项目，而不因已有原型就坚持重复建设。

## 六 技术路线与数据治理

交互层采用语义化控件和普通页面导航；核心算法独立于界面，处理字幕时间、备份校验、段落拆分和颜色计算。表达板、阅读和任务模块分别管理状态，临时文字默认不落盘。用户主动保存的数据集中为一个带版本号的本机 JSON 结构，导入先验证再确认，避免错误文件部分覆盖。

语音只选择浏览器标记为本地的声音；没有声音时保留文字及大字路径。网页检查以未挂载模板解析源码，不执行输入脚本，不加载其中资源。字幕与媒体仅由用户在当前设备打开，不接入识别服务，也不上传服务器。

| 风险点 | 设计控制 | 验证方式 |
| --- | --- | --- |
| 敏感文字泄露 | 默认不保存 无追踪 不自动上传 | 网络请求检查 存储行为测试 |
| 已存内容被破坏 | 结构验证 异常暂停写入 明确确认 | 损坏与冲突备份样本 |
| 键盘陷阱 | 正常 Tab 路径 扫描可退出 | 键盘及外接开关任务 |
| 自动检查误导 | 明确线索范围 人工复核说明 | 好坏源码与反例测试 |
| 设备语音差异 | 本地语音检测 文字兜底 | 多设备与断网检查 |

本机存储并不等于加密或身份保护。共用设备上的其他使用者、扩展或同源代码仍可能读取数据。项目不收集用户原文作为遥测，不将健康或身份资料存入公开仓库。研究记录采用最少信息、代号及明确授权；任何后续云同步都应作为新功能单独评估。

## 九 验收指标与评估方法

| 指标 | 拟定目标 | 计算与证据 |
| --- | --- | --- |
| 当事人参与 | 20至24 名 自愿可退出 | 同意记录及匿名任务记录 |

这些是拟验收目标，不是已取得结果。除任务完成外，还需收集误选与恢复、主观负担、偏好及是否愿意继续使用。不得用少数受试者结果证明普遍有效，更不得推导临床疗效。

## 十二 风险应对与退出条件

| 风险 | 可能影响 | 应对与暂停条件 |
| --- | --- | --- |
| 原型与真实需求不匹配 | 维护无用功能 | 反复不适用或成熟工具明显更合适时停止扩展 |
| 参与者被动同意 | 研究结果失真及伤害自主性 | 提供独立表达与退出渠道 不以协助者同意代替 |
| 兼容问题 | 无法使用或误触发 | 分层公布支持范围 阻断未修复不扩大试点 |
| 数据泄露或丢失 | 敏感文字暴露 | 最少保存 备份 授权 事故暂停与告知流程 |
| 资金和人员未落实 | 进度失控 | 不承诺未签资源 缩小到最有证据的模块 |
| 误导性传播 | 被当成医疗或合规保障 | 发布前审查能力描述 禁用无法证明的表述 |

第一轮若大多数参与者认为原有工具更易用，应调整方向或贡献现有项目，不能仅因已投入开发就继续扩张。项目不设置必须完成的身体或医疗任务，不将任务卡当作服药、安全操作或紧急报警系统。

## 十三 预期社会价值与持续维护

预期价值是让部分使用者多一种自主完成沟通、阅读或低风险任务的方式，并让服务点理解自己的内容障碍。是否实现，要由实际任务与当事人反馈证明。项目不承诺减少疾病、康复改善或替代人员服务。

计划保持基础工具免费开放，通过机构适配、培训、维护或公益支持承担持续成本。任何机构服务与研究数据应分开，不以个人数据交易为收入来源。结束资助前应确定维护负责人、问题处理入口和停止服务时的数据导出方式。
